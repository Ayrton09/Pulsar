# ADR-0004 — Application-generated UUIDv7 as the single ID strategy

Status: Accepted (2026-10-01) — implemented in Phase 1 (`Guid.CreateVersion7`, strongly typed ids).

## Context
IDs appear in the database, URLs, the agent protocol and node logs. A single strategy suited to distributed systems is required.

## Decision
Every entity uses a `uuid` holding a UUIDv7 generated in the domain with `Guid.CreateVersion7()` (.NET 9+), assigned when the entity is created (not by the database). Strongly typed IDs in Domain/Application; plain `Guid` in DTOs and the protocol. Resources that need a short identifier (Windows account name, folder) use a separate random `short_id`.

## Alternatives
- `bigint` identity: compact, but reveals volume, is unknown before insert and is a poor fit with distributed agents.
- UUIDv4: purely random; fragments B-tree indexes.
- Generation in PostgreSQL (`uuidv7()` in PG 18): would tie the design to a minimum PostgreSQL version and the ID would be unknown before persisting.

## Consequences
- Time-ordered indexes, IDs known before saving (useful for operations and commands).
- UUIDv7 reveals the creation time: acceptable. Secrets and tokens are never UUIDs (always 256 bits from the CSPRNG).
